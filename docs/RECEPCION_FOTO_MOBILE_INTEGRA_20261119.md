# Recepcion Mobile: integridad de fotografia

Desarrollo sobre Motor 42005eb; no instalado. Un envio repetido conserva su JSON y estado. Si la foto coincide con el SHA registrado, no se reescribe ni se toma el lock. Si falta o es corrupta, se toma el lock del envio, se comprueban identidad, MIME y SHA del registro, y se verifica tamano y SHA del contenido temporal antes de reemplazar atomicamente el original. Cloud ya comprueba tamano y SHA declarados por su lease antes de entregar los bytes al repositorio. Se admiten los formatos existentes JPEG, PNG y WebP.

En PULL un ERROR persistido con fotografia integra sigue omitido. Si falta o esta corrupta, PULL puede descargar y reparar la fotografia bajo las guardias existentes, pero deja el JSON y el ERROR intactos: no ejecuta OCR, no confirma Cloud y no toma decisiones humanas. Un SHA de Cloud distinto al local se rechaza. La recuperacion funcional sigue requiriendo el procedimiento explicito autorizado con custodia v2 (recuperador b04b897), comprobacion de ausencia de fila y demas validaciones. No integra ni modifica ese recuperador.

El PULL solo ve envios ofrecidos por Cloud: un envio ya confirmado que no vuelva a ofrecerse no se busca ni repara automaticamente. Una perdida de lease, error de disco o corte puede dejar una operacion incompleta: el archivo temporal no es el original y la custodia sigue su propio diario y reglas de alineacion. No reintentar una recuperacion funcional sin revisar el estado del envio, dataset y custodia. La prueba de interrupcion simula excepcion antes de reemplazo; no demuestra durabilidad fisica frente a todos los cortes de energia.
